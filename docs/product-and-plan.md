# openJudge 首版：产品方向与执行记录

## 目标与边界

创业者把一个具体的分歧写清楚，邀请其他人先独立表态、再给出理由，获得可以帮助自己判断的不同视角。审批是参考，不承诺提高决策正确率，也不替发起人做决定。

参照「钱包请等等」的公开审批与先表态再看结果，结合创业决策增加两个方案和「机会 / 执行 / 风险」视角。第一版不做营销页面、会员支付、私聊、专家撮合或虚构的社区数据；这些需要真实需求与运营准备后再决定。

## 迪士尼策略与逆向推演

- 梦想家：讨论希望达到的结果与可能的机会。
- 实干家：评审要说明实际执行的条件或下一步。
- 批评家：主动寻找可能失败的原因和缺失的信息。
- 逆向看失败：敏感商业信息被公开、大家被现有票数带偏、无理由的热闹投票、把多数票误认为正确答案。对应方案为发布前的明确提醒和确认、先投票后看结果、提供理由及视角、界面强调最终决策权属于发起人。

共同范式是降低决策负荷：把模糊问题外化成有限选项，通过独立视角减少从众，用具体理由而不是权威标签帮助比较；这些是产品假设，尚需真实用户验证。

## 隐私边界

草稿只存当前浏览器。发布后内容对能够访问站点的人可见，发布前提醒去掉姓名、公司、联系方式、合同、代码和可识别数据；界面只展示匿名称呼。平台仍需识别账户以防重复投票和管理自己的内容，因此这不是端到端匿名或保密承诺。作者可以删除自己发布的内容，但无法撤回别人已经复制的信息。不提供没有访问控制的「私密链接」假功能。

## 2026-11-08：补齐决策闭环

### 问题与决定

私有预览只有一位真实用户；原有的三条示例不可审批，因此无法体验「看问题 → 审批」。继续保持站点私有，示例增加清晰标注的本机练习，不冒充真实帖子或真实用户。真实多人流程采用站内对话：评审者明确选择是否愿意被联系，只有决策作者可以就该条评审发起对话，双方可以在消息中回复；站内对话不会自动暴露邮箱或其他联系方式，平台仍可处理和存储消息。
